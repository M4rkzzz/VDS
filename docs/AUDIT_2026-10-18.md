# VDS 全模块审计与烟测（2026-10-18）

## 范围与方法

基于 `939b052` 及本次窗口修复，覆盖 server、desktop/main/preload、renderer、vds_web、media-agent 和增强 ICE。执行完整现有回归，再针对近期 GPU 呈现、采集预览、生命周期、媒体边界、房间身份及差分更新复核代码和实际链路。这是全模块回归与关键代码审阅，不等于逐行证明所有代码无缺陷。

环境：Windows、本机 AMD 硬件路径、Node 22.20.0、Electron 42.11.11、CMake 4.2.3、Release 原生构建。媒体烟测依次运行，使用独立本地房间、配置和自建进程。没有操作用户已安装客户端、用户房间或 GameViewer。

## 本轮确认并修复

### 中：原生独立窗口忽略隐藏配置

`native_video_surface.cpp` 和 `native_live_preview.cpp` 创建窗口时无条件带 `WS_VISIBLE`；独立模式又无条件 `SW_SHOW`，布局更新则直接返回。结果是 `embedded:false, visible:false` 仍可能弹出窗口，后续隐藏配置也不生效。嵌入模式也存在先创建可见窗口、再隐藏的短暂窗口期。

创建窗口时去掉无条件可见样式，按配置显隐；显示使用不激活方式，独立窗口更新通过 `ShowWindowAsync` 应用。没有新增线程、定时器或媒体运行配额。

回归包括真实 HWND 初始隐藏、显示后再隐藏，以及八轮真实 WGC 预览的窗口隐藏检查。预览各轮持续增长到 13 帧，采集状态正常，停止重开通过。

### 新增覆盖：GPU 播放中的编码尺寸变化

原测试只覆盖观看窗口尺寸变化。本轮加入同一观看窗口中发送源从 160×96 切换到 320×180 的场景，检查实际 GPU 输出像素、持续呈现、零 CPU 回读和无意外回退，再验证呈现故障后 GDI 接续。

### 修正隐藏窗口测试的绘制触发依据

首次修复后完整原生回归为 26/27：GDI 1080p60/PES 场景绘制 250/280 帧，低于原有 252 帧门槛。该夹具通过 `snapshot.reason` 判断是否有新帧；但新帧发布与旧帧绘制异步，旧帧完成可以把诊断文字覆盖为 `native-frame-rendered`，诊断文字不能充当待绘制标志。

改为测试构建专用的帧序号比较，按实际最新帧与已绘制帧决定是否泵 WM_PAINT；没有降低 90% 门槛，也没有恢复高频重绘旧帧来抬高 CPU。该字段不进入生产 agent。首次失败保留在 `tmp/full-audit-native-final.log`，后续验证单独记录，不能把首次运行写成全通过。

针对性复测通过：GDI 272/280、GPU 275/280，GPU CPU 回读为 0；各自 280 个视频包、220 个 AAC 包均完整解码。GPU 换编码尺寸场景检查 109 次输出，呈现 108 次，故障后 GDI 接续 35 帧。旧夹具下较少的 GDI 绘制次数使先前单轮 CPU 对比不适合作为公平性能结论，历史数据仅保留供追溯。

最终完整 CTest **27/27**，126.57 秒。该轮 GDI 274/280、GPU 279/280，实际捕获到 **22 次“存在待绘制新帧但诊断文字已是 rendered”**，证实旧触发依据不可靠；GPU 仍然零 CPU 回读。原有阈值未改，且单独复测与完整回归均通过。

## 既有高风险项复核

- 原生分片先校验总长度、分片形状与索引，再分配；未完成帧按连接及全局统计内存，重复片不重复计费，关闭释放。Annex-B 有增量扫描及未完成数据防护。
- 发送背压按完整帧处理，丢弃后等待新关键帧；关闭顺序先停生产者与发送绑定，再关 transport/relay。
- 公网管理快照仅包含公开房间；全部房间只在默认 loopback 管理服务提供。没有重新引入管理令牌。六位一次性房号规则保留。
- join 拒绝房主/保留 ID，重连验证 session token；转发按白名单重建；WebSocket 心跳回收半开连接；payload 格式归一化不再被重复定义覆盖。
- IPC 检查 sender/main frame 与页面来源，远端 ICE 参数正规化和代次隔离有回归。
- 更新强制可信 HTTPS 来源，清单使用离线 Ed25519 签名；签名、下载哈希及差分基线均有拒绝篡改测试。这不是 Windows Authenticode 签名。

以上由源码复核和对应回归支持；没有据此声称互联网服务经过完整渗透测试。

## 尚存事项与验证边界

1. **构建依赖中危告警**：全依赖 `npm audit` 为 8 个 moderate 条目，来自同一个 `sprintf-js` 问题，经 roarr/global-agent/@electron/get 传播到 electron-builder。根项目生产依赖及 server 审计均为 0。上游 [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) 标记无修复版本；需要攻击者控制格式字符串才能触发超大精度导致的异常/拒绝服务。没有采用 npm 建议的旧 electron-builder 降级。仍应跟踪上游补丁。
2. **真实网络与硬件**：随机 NAT 仿真不等于移动/联通跨运营商实机成功率；严格双对称 NAT 仍可能无法直连。没有引入 TURN。
3. **显示与音频**：隐藏窗口/离屏渲染、实际解码和 GPU 输出像素可验证软件路径；未完成物理显示器/VSync 延迟、不同厂商显卡、HDR/10-bit、扬声器听感及目标应用进程音频的人工验收。音频回归不能证明任意应用均可捕获。
4. **发布与部署**：本轮未制作或发布新安装包，正式版本仍为 1.7.10；未重启 NAS/FRP。Authenticode、跨平台 CI 和长期耐久运行仍不在本次完成项中。
