# Media-agent 翻新记录（2026-10-18）

本轮按“关键部分、保持轻量”的范围处理连接、采集恢复与播放时钟。仍为纯 P2P，没有配置 TURN，也没有新增媒体帧率、码率、分辨率或会话时长限制。

## GameViewer 参考的证据边界

本地 REA 提供的是已安装 GameViewer 的二进制、反汇编和反编译证据，并非完整源码。目标 `streamer.dll` 的 SHA256 为 `ab8ade084c4f714fe5b21d1324b7e5d13e41bb036d4382e4bc231383b3d56e79`。VDS 独立实现对应机制，未把厂商函数或整个协议栈复制进项目。

- 音频：已有 `REA/reports/gameviewer-audio-rea.md` 和代码证据确认 WASAPI loopback、设备通知与重启。VDS 保留进程级 loopback；不能照搬桌面默认设备绑定，否则会改变进程音频选择的含义。
- 视频：`REA/scripts/vds-media-xrefs.py` 在同一目标中找到采集适配器变化后重启、设备移除、呈现设备丢失，以及 flip-discard → flip-sequential → blit 回退、最大帧延迟 1 等字符串的实际代码引用。字符串引用只用于定位，不单独作为完整控制流的证明；后续 REA MCP 伪代码与原始结果保留在本地 REA。
- NAT：此前已用 REA MCP 分析随机/线性映射组合、多 socket、选路和清理函数。本轮对应落地到 VDS 自有 ICE 栈；浏览器没有原生 socket 控制接口。

## 现在的实际结构

采集侧：WGC 获取窗口/显示器帧，复用 CPU BGRA 缓冲，在回读前按源节奏筛选；FFmpeg 硬件编码输出 Annex-B 访问单元，原生 DataChannel 分片发送。WASAPI 进程回环经本地回调送入音频编码与分发，逐包 JSON/base64 默认关闭。OBS 是另一个采集入口。

播放侧：压缩帧重排、引用链恢复及关键帧请求 → FFmpeg 解码 → 有界待呈现帧队列 → 源时间戳/音频设备时钟驱动的调度 → Win32 GDI 呈现。可用时采用 D3D11VA/DXVA2 硬解，但随后仍需 CPU 回读和像素转换；目前还不是 GPU 纹理直接呈现的 SwapChain。网页侧保持 WebCodecs 独立播放器。

## 第二轮：播放解码器故障恢复

继续对照 GameViewer 呈现设备失效处理证据，确认 VDS 的独立缺口：硬件帧回读失败只更新错误，接收解码结果失败也没有重建设备；损坏的上下文可能持续被复用。此轮没有移植厂商代码，也没有新增运行时依赖。

- 解码提交、输出与 GPU 回读进入统一恢复路径，由原解码工作线程处理资源释放。保留窗口、连接、源代次及参数集，清除旧引用帧并请求关键帧。
- 硬解的非坏数据错误、硬件回读错误会用全新上下文回退软件解码；当前 surface 保持已工作的软件路径，重新加入/创建 surface 时再次探测硬件，避免每个关键帧重新撞上故障设备。软件回退可能增加 CPU 占用，不限制媒体规格。
- `AVERROR_INVALIDDATA` 只清理解码引用链，不把普通坏帧当作显卡故障。软件解码器发生其他错误时也能重建。
- 初始硬解打开失败后的软件尝试同样分配新上下文，不复用部分初始化的对象。恢复打开失败会保留原始错误及重开失败原因。
- 诊断新增 `decoderBackend`、`decoderRebuilds`、`hardwareFallbacks`、`lastDecoderFailure`；恢复后活动错误清除，历史故障仍可查。

故障注入仅编译进原生集成测试，不进入 agent 的配置、IPC 或二进制。真实 H264 → D3D11VA → GDI 测试中，分别注入提交、输出、GPU 回读错误，同一个 surface 的绘制计数从 18 增长到 72、72、71，后续 IDR 特意移除 SPS/PPS，验证恢复复用了当前源配置；普通坏帧用例从 18 增长到 72，保持 D3D11VA，重建和降级次数均为零。没有重置用户显卡，不能将返回值注入当作真实驱动崩溃验收。

最终 Release 构建、完整原生 CTest 27/27（112.64 秒）及架构检查通过；包含 30/60fps、1080p60 同步音视频突发、关闭重开及新增恢复测试。构建产物与 runtime 的 EXE 哈希一致。构建日志 `tmp/decoder-recovery-build-final.log`，原生结果 `tmp/decoder-recovery-native-final.log`，故障注入详细计数 `tmp/decoder-recovery-test.log`；本轮未修改网页播放器，也未重复上一轮 JS 全量测试。

本轮源码 Electron + runtime 的本地 WGC/P2P 原生观看两轮十秒烟测通过，绘制计数分别 13→303、12→298；离开重进、UI 脚本点击与主进程 IPC 正常，自建进程全部正常退出。窗口隐藏，仍采用上一轮的 UI 过渡等待替换，未替换媒体链路。正式安装包仍为 1.7.10，本次源码改进尚未作为新版本发布。

“超过参考实现”需要同机同场景比较首次出帧时间、故障恢复时间、延迟分位数与 CPU/GPU 占用。本轮证明恢复能力补齐，不宣称整体性能超过 GameViewer；GPU 直出呈现和编码器设备重建仍待后续实现。

## 本轮改动

1. **视频采集恢复与静态画面**：WGC 等帧超时时查询 D3D 设备移除状态，避免显卡失效被无限当作普通超时。发送线程在运行期回读失败时关闭旧采集源、在原线程重建，保留编码器输入和连接；失败时退避，停止仍可打断等待。源关闭和无效输出等错误保留退出语义。真实烟测还复现静态桌面仅有少量新帧、首个 IDR 早于通道就绪后长期没有后续关键帧的问题。没有新帧时按用户帧率复用已有 CPU 像素，保持编码器节奏与后续关键帧；不再次 GPU 回读，不在停顿后补发积压帧。`sourceFramesRepeated` 与实际 `sourceFramesCaptured` 分开统计，不把重复画面算作新采集。
2. **音频采集恢复**：建立过的进程回环遇到设备失效、资源失效或音频服务中断时，在同一工作线程重开客户端，保留 PID、进程选择、回调与累计采集计数。首次启动失败仍返回给调用方，权限/配置错误不循环重试；恢复等待可立即取消。
3. **播放时钟单调性**：真实音频设备烟测复现粗粒度位置重复上报后软件插值倒退。加入确定性回归，确认旧代码失败；用已返回的采样位置作为插值下限，硬件追上后恢复正常推进。停滞和过期位置仍失效，源重置会清除下限，不靠增大缓冲掩盖问题。
4. **随机 NAT 多 socket**：原生 ICE 在协商能力与当前 ufrag 校验后探索辅助 socket，使用标准认证 STUN、随机事务 ID 和同 socket 选路/媒体发送。未选中的 socket 会清理。详见 [ICE 补丁说明](../media-agent/third_party/ice-patches/README.md)。

## 验证与限制

Release 构建与最终 runtime 的 EXE 哈希一致；最终完整原生 CTest 27/27、桌面 JS 268/268、JS NAT/STUN/代次 27/27、架构边界检查通过。WGC/AMD AMF→P2P→WebCodecs 720p30 七阶段通过：20.150 秒新增 595 帧（29.53fps），接力断开恢复后 20.173 秒新增 596 帧（29.54fps），无三秒停帧；持续阶段各丢弃一帧，切换时另有丢帧。帧数包含合法的静态画面复用，不代表桌面每帧像素都变化。

最终构建的 OBS/AAC 音视频八阶段回归通过，覆盖离开重进、重载、两轮同连接源重启及接力断开恢复。持续 20.021 秒新增 590 视频帧和 926 音频块，切换时有丢帧；无警告或控制台错误，原生 agent 正常停止。

最终源码 Electron + 新 runtime 的两轮 720p30 原生观看，每轮十秒，播放计数分别 40→339、36→333，离开重进、调试按钮脚本点击及主进程 IPC 通过；新多 socket 能力字段、STUN 池与代次关闭检查通过。测试窗口隐藏，因此在页面初始化完成后仅替换 UI 过渡的 `nextPaint` 等待；没有替换采集、编码、传输或原生解码。最初夹具沿用安装包 URL 和过早替换时序，曾超时，修正后通过。这不是人工鼠标或物理显示器验收。窗口和房主 agent 正常退出，零自建进程残留。

随机 NAT 使用独立种子的双端随机端口排列、按目的端点映射、严格端点过滤和真实 ICE/DTLS/SCTP；有限 256 端口分配窗口不代表所有路由器。旧策略 0/6，新策略本轮 4/6；成功的四组均有真实辅助 socket 获选，选路后继续七秒数据回显，并检查清理后端口可复用。另测 stable/random 原路径可正常获选，不强制绕道辅助 socket。损坏认证包不能伪造连接就绪。

WASAPI 恢复控制流使用故障注入覆盖设备错误、首次失败、成功重开和停止取消；没有切换用户默认音频设备、停止系统音频服务或重置显卡。显卡重置若同时杀死硬件编码器，仍需编码器层恢复，不能将仅采集源恢复宣称为整条 GPU 链路已验收。

完整 GPU 直出 SwapChain、跨适配器纹理传输及采集/编码共享是后续独立改造项，本轮不宣称完成 GameViewer 全栈替换。新增的退避和短期探测预算只约束异常恢复或建连工作，不是媒体运行配额。
