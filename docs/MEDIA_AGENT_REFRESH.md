## 后续补齐：候选组重规划与显示恢复（2026-10-18）

基于 `380eca6` 后的新一轮 UU 静态证据，独立补齐两条路径，正式安装包版本仍为 1.7.10，未发布新包。

- **远端出口调度**：随机打洞按当前 ICE 凭据将远端 IPv4 srflx 分组，先按映射置信度、候选优先级与地址排序，再逐组轮换。它改进的是现有 agent 内的远端出口探索，没有把混合的本地网卡观测冒充成完整本地×远端接口矩阵。
- **新探索与重传分离**：每个五秒计划内重传两轮；尚未选路时，下一计划更换出口、随机种子与完整事务 ID，复用现有辅助 socket。遍历出口组后逐渐扩大到完整非特权端口空间。旧计划查询表销毁，鉴权、代次隔离、nomination、consent 与获胜 socket 复用不变。标准 ICE 管整体连接超时；停止或连通后释放未选中的 socket。
- **显示就绪调度**：获取并释放 DXGI frame-latency handle，呈现前只做零超时就绪检查。等待置于原生窗口消息循环，与输入和关闭消息一起处理；保留最新待呈现帧，GPU 忙时即使没有新输入也会重试。测试首次抓到隐藏窗口的 `UpdateWindow` 不触发重绘，已改为同一个原生窗口线程分发 `WM_PAINT`，不跨线程等待 Electron owner。
- **GPU 回退可恢复**：呈现失败保留 GDI 播放；从两秒开始、最长三十二秒的异常重建退避到期后，后续合适帧重新尝试 GPU。成功清除失败连续计数，新建解码器清除旧 cooldown。不在每帧失败时反复创建 GPU 资源，也不限制正常媒体节奏。

## 现在的实际结构

采集侧：WGC 获取窗口/显示器帧，复用 CPU BGRA 缓冲，在回读前按源节奏筛选；FFmpeg 硬件编码输出 Annex-B 访问单元，原生 DataChannel 分片发送。WASAPI 进程回环经本地回调送入音频编码与分发，逐包 JSON/base64 默认关闭。OBS 是另一个采集入口。

播放侧：压缩帧重排、引用链恢复及关键帧请求 → FFmpeg 解码 → 有界待呈现帧队列 → 源时间戳/音频设备时钟驱动的调度。D3D11VA 的 SDR/NV12 渐进帧现在直接经 Video Processor → SwapChain 呈现；其他格式、DXVA2、软件解码或 GPU 呈现失败走 CPU 转换/GDI 兼容路径。网页侧保持 WebCodecs 独立播放器。

## 第三轮：D3D11 解码纹理直接呈现

后续全模块审计修正了隐藏窗口夹具依赖诊断文字的绘制竞态，见 [审计报告](AUDIT_2026-10-18.md)。本节末的旧单轮 CPU 数字保留用于追溯，不再用于公平性能比较；GPU 直接呈现、输出像素及零 CPU 回读由修正后的回归继续验证。

新增独立模块 `native_d3d11_presenter`，在现有原生窗口线程工作，不新增线程或媒体定时器。正常 D3D11VA/NV12 路径将已解码 AVFrame 的所有权移交给最新待绘制图像，保留纹理引用直到提交 Video Processor，直接在 GPU 完成色彩转换、缩放和黑边。没有 `av_hwframe_transfer_data`、CPU BGRA 缓冲或 swscale 转换。只保留最新待绘制图像，仍沿用原有时间戳/音频时钟调度；重复 WM_PAINT 不重复处理同一帧，窗口尺寸变化时才重绘旧帧。

SwapChain 使用独立的无激活、鼠标穿透子窗口，避免 Flip 模型和 GDI 在同一个 HWND 上交替绘制；参见 [Microsoft Flip Model 文档](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model)。优先 flip-discard，再尝试 flip-sequential；硬件不支持或运行期呈现失败则销毁 GPU 子窗口，继续 GDI。视频处理器和 FFmpeg 共用解码设备及其锁，Present 在锁外执行；采用非阻塞 Present 和最多一个排队帧，输入/输出描述使用相同源帧率，不做帧率转换或增加 FPS 上限。

本轮接管的是已覆盖的 SDR/NV12、BT.601/BT.709 渐进内容。HDR、10-bit、其他色彩空间和隔行内容保留原路径，未宣称 HDR 色调映射或跨显卡直传完成。新增诊断 `gpuPresentedFrames`、`cpuReadbackFrames`、`gpuPresentFallbacks`、`lastPresentFailure`，可区分真正走了 GPU 路径还是兼容回退。

真实 H264 硬解后的 GPU 输出像素测试覆盖变化画面、黑边、尺寸变化、重复重绘去重；测试专用回读验证 Video Processor 的输出纹理，不编入生产 agent。注入呈现失败后自动拆除子窗口并恢复 GDI，保留健康硬解器；另验证 GPU 正在呈现时解码器失败能回退软件解码继续绘制。测试没有切换系统显示设置或重置用户显卡。

最终源码 Electron + runtime 的本地 WGC/P2P 两轮十秒观看均使用 `ffmpeg-d3d11-video-processor-swapchain`，GPU 呈现计数分别 15→298、13→295；CPU 回读为零，无呈现回退。离开重进、UI 脚本点击和主进程 IPC 通过，自建进程正常退出且无残留。窗口隐藏，因此不把 Present 成功计数当作物理显示器可见帧、端到端延迟或 VSync 测量。正式安装包尚未更新。

## 第二轮：播放解码器故障恢复

继续对照 GameViewer 呈现设备失效处理证据，确认 VDS 的独立缺口：硬件帧回读失败只更新错误，接收解码结果失败也没有重建设备；损坏的上下文可能持续被复用。此轮没有移植厂商代码，也没有新增运行时依赖。

- 解码提交、输出与 GPU 回读进入统一恢复路径，由原解码工作线程处理资源释放。保留窗口、连接、源代次及参数集，清除旧引用帧并请求关键帧。
- 硬解的非坏数据错误、硬件回读错误会用全新上下文回退软件解码；当前 surface 保持已工作的软件路径，重新加入/创建 surface 时再次探测硬件，避免每个关键帧重新撞上故障设备。软件回退可能增加 CPU 占用，不限制媒体规格。
- `AVERROR_INVALIDDATA` 只清理解码引用链，不把普通坏帧当作显卡故障。软件解码器发生其他错误时也能重建。
- 初始硬解打开失败后的软件尝试同样分配新上下文，不复用部分初始化的对象。恢复打开失败会保留原始错误及重开失败原因。

## 本轮改动

1. **视频采集恢复与静态画面**：WGC 等帧超时时查询 D3D 设备移除状态，避免显卡失效被无限当作普通超时。发送线程在运行期回读失败时关闭旧采集源、在原线程重建，保留编码器输入和连接；失败时退避，停止仍可打断等待。源关闭和无效输出等错误保留退出语义。真实烟测还复现静态桌面仅有少量新帧、首个 IDR 早于通道就绪后长期没有后续关键帧的问题。没有新帧时按用户帧率复用已有 CPU 像素，保持编码器节奏与后续关键帧；不再次 GPU 回读，不在停顿后补发积压帧。`sourceFramesRepeated` 与实际 `sourceFramesCaptured` 分开统计，不把重复画面算作新采集。
2. **音频采集恢复**：建立过的进程回环遇到设备失效、资源失效或音频服务中断时，在同一工作线程重开客户端，保留 PID、进程选择、回调与累计采集计数。首次启动失败仍返回给调用方，权限/配置错误不循环重试；恢复等待可立即取消。
3. **播放时钟单调性**：真实音频设备烟测复现粗粒度位置重复上报后软件插值倒退。加入确定性回归，确认旧代码失败；用已返回的采样位置作为插值下限，硬件追上后恢复正常推进。停滞和过期位置仍失效，源重置会清除下限，不靠增大缓冲掩盖问题。
4. **随机 NAT 多 socket**：原生 ICE 在协商能力与当前 ufrag 校验后探索辅助 socket，使用标准认证 STUN、随机事务 ID 和同 socket 选路/媒体发送。未选中的 socket 会清理。详见 [ICE 补丁说明](../media-agent/third_party/ice-patches/README.md)。
